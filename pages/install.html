Getting it running

Iris-Lite targets Debian on a Raspberry Pi 4B. The Python side runs anywhere OpenCV does — GPIO disables itself automatically off Linux — but the compression engine needs POSIX shared memory, so the full system is Linux-only.

Requirements

System

  • Debian Linux (Raspberry Pi OS)
  • Python 3.12.7
  • GCC 11+, C++17
  • CMake 3.16+
  • FFmpeg with h264_v4l2m2m

Python packages

  • opencv-contrib-python — the bgsegm module is required
  • numpy
  • pyaudio
  • ai-edge-litert
  • RPi.GPIO
Not optional

Plain opencv-python will not work. Both background subtractors the detectors rely on — CNT and GSOC — live in cv2.bgsegm, which only ships in the contrib build.

Installation

  1. System packages

    sudo apt update && sudo apt upgrade -y
sudo apt install -y ffmpeg libopencv-dev python3-pip cmake build-essential

    libopencv-dev also provides the Haar cascade XML the compressor's face term loads from /usr/share/opencv4/haarcascades/.

  2. Python packages

    pip3 install opencv-contrib-python numpy pyaudio ai-edge-litert RPi.GPIO

  3. Clone

    git clone https://github.com/AbhiramV010/Iris-Lite.git
cd Iris-Lite

  4. Build the compression engine

    cd Compression
mkdir -p build && cd build
cmake ..
make -j4
cd ../..

    Produces Compression/build/PerceptualCompressor. CMake defaults to a Release build with -O3 -mcpu=cortex-a72, which is correct for the Pi 4B and wrong for anything else — override CMAKE_CXX_FLAGS_RELEASE if you are building elsewhere.

  5. Prepare clip storage

    sudo mkdir -p /mnt/clipDrive/clips
sudo chmod 777 /mnt/clipDrive/clips

    The engine creates these directories itself on startup, but it cannot mount a drive for you. If /mnt/clipDrive is meant to be external storage, mount it before launching.

Running

From the repository root: 

bash startIrisLite.sh

The launcher opens seven uxterm windows — top plus the six system processes — in a fixed order, with a progress bar between steps. That order matters: main.py creates the ring blocks, startCamera.py gets five seconds to bring the camera up, and the detectors are started only afterwards because each raises an error if the live frame block is missing.

All six must be running for the system to work end to end:

WindowCommand
Main Toolpython3 ./Decision/main.py
Camera Utilitypython3 ./Decision/startCamera.py
Detector Pipelinepython3 ./Decision/detector_pipeline.py
Listener Toolpython3 ./Decision/listener.py
Zone Monitorpython3 ./Decision/zone_monitor.py
Compression Systemcd Compression && sudo build/./PerceptualCompressor
Bash, not zsh

The launcher uses bash array and arithmetic syntax. Run it with bash explicitly. The compressor is started with sudo because it needs to map shared memory created by another user's process; it must also be launched from within Compression/, since it loads config/config.json by relative path.

Stop the system by closing the windows, or by pressing x in any OpenCV preview window to break that process's loop cleanly.

Demo scripts

Three cut-down launchers in demos/ bring up the minimum needed to demonstrate one detector — the buffer manager, the camera, and the detector itself. Useful for tuning thresholds without the other two competing for CPU.

ScriptStarts
demos/det_pipe.shBuffer manager, camera, two-tier motion detector
demos/sound.shBuffer manager, camera, audio listener
demos/zone.shBuffer manager, camera, zone monitor

None of the demo scripts start the compressor, so events are raised and logged but no clips are written.

Configuration

The compression engine reads Compression/config/config.json at startup. Every key is optional and falls back to the default compiled into Config.hpp. 

{
  "encode_width": 640,
  "encode_height": 360,

  "perceptual_width": 320,
  "perceptual_height": 180,

  "fps": 24,
  "crf": 22,

  "use_faces": true,
  "use_motion": true,
  "use_edges": true,

  "face_model_path": "/usr/share/opencv4/haarcascades/haarcascade_frontalface_default.xml",
  "face_detect_interval": 10
}

Loading is validated: a non-positive encode resolution aborts startup, an fps outside 1–60 is reset to 24 with a warning, and a non-positive face interval is reset to 10. Detector thresholds are not configurable this way — they are constants at the top of each Python file, listed in the reference.

Troubleshooting

Camera not detected

Confirm the device exists and advertises MJPG at 1920×1080: 

v4l2-ctl --list-formats-ext

startCamera.py prints a warning if the negotiated codec is not MJPG and continues anyway, but a YUYV-only camera will not sustain 1080p over USB and the capture loop will stall.

Shared memory error on startup

A hard kill leaves blocks behind. Clear the live frame block: 

python3 -c "from multiprocessing import shared_memory; \
shared_memory.SharedMemory('iris_live_frame').unlink()"

The ring blocks are larger and worth clearing too if memory looks wrong — the same call works for iris_frame_buffer_data, iris_frame_sizes, iris_frame_head_tail, iris_concern_indices, iris_indices and iris_lite_audio. They also appear as files under /dev/shm/.

Compression engine not encoding

First check the hardware encoder is present: 

ffmpeg -codecs | grep h264_v4l2m2m

If it is missing the engine falls back to libx264 and logs the switch, so an absent encoder slows things down rather than breaking them. If nothing is written at all, check that /mnt/clipDrive/clips/ is writable by the user running the binary, and that the engine was launched from inside Compression/ so it could find its config.

Audio device not found

listener.py scans for an input device whose name contains usb or hw, then falls back to the system default, then exits. List what is available: 

arecord -l

GPIO errors off Linux

Expected. sensor_helper.py disables GPIO entirely when platform.system() is not Linux and prints a notice. Detection works normally; the sensor fields on each event are simply left unset.

No display attached

main.py and zone_monitor.py call cv2.imshow, catch the failure and warn that they are running headlessly. This is safe. Removing those calls entirely reclaims a meaningful amount of CPU on a deployed unit — see results.

Documentation drift

The repository README.md refers to a launcher named IRIS_Lite.sh, a clips/ source directory and a storage path of /clipDrive/clips/. The current tree uses startIrisLite.sh, Decision/ and /mnt/clipDrive/clips/ respectively. These pages follow the code.
