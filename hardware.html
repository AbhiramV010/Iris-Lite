04 · Hardware & power

The physical unit

One Raspberry Pi 4B, two USB peripherals, two GPIO sensors and a printed case. The only custom electronics in the project sits outside all of that, between the wall and the battery, deciding when it is a good time to charge.

Sensor wiring

Both sensors use the same pattern: one leg to the GPIO pin, one to ground, with the Pi's internal pull-up doing the rest. No external resistors. 

gpio.setmode(gpio.BCM)
gpio.setup(pin, gpio.IN, pull_up_down=gpio.PUD_UP)
gpio.add_event_detect(pin, gpio.FALLING,
                      callback=update_time,
                      bouncetime=200)

The callback records a timestamp rather than setting a flag. When a detector builds a CaptureClass it asks whether the pin fired within the last ten seconds, which is the question that actually matters — a reed switch closes for a few milliseconds as a door swings, and polling the pin level at event-construction time would almost always read nothing.

Pin numbering

BCM numbering throughout, not physical pin numbers. BCM 17 is physical pin 11 and BCM 27 is physical pin 13.

Thermals and load

Over a ten-minute instrumented run with all six processes active, the package settled at 68 °C with both passive and active cooling fitted. The Pi 4B begins throttling at 80 °C, so there is headroom, but not a large amount of it for a sealed outdoor enclosure in summer.

This is also the reason SystemGovernor reads the thermal zone at all. The compressor is the only component that can voluntarily reduce its own load, and it uses temperature as 30% of its pressure signal specifically so that a warm board produces cheaper encodes before the kernel starts throttling every core.

Full CPU figures are on the results page.

Carbon-aware charging

Charging is handled entirely off-board by a separate custom circuit, so nothing on this page changes if it is left out — the Pi simply runs from mains like any other.

AbhiramV010/CarbonAwareCharge

The unit runs from its battery by default and tops up when the grid it is attached to is running clean. Grid carbon intensity swings substantially over a day depending on how much of the local mix is renewable, and a device that only needs to charge sometime can wait for the cheap end of that curve without any change in behaviour that a user would notice.

Failure mode

A status GPIO blinks when Wi-Fi is unavailable or the carbon query fails. The board fails loudly rather than quietly charging on dirty power, which is the right default for a feature whose entire value is in when it acts — a silent fallback would be indistinguishable from the feature working.

Privacy by construction

The privacy properties here are mostly consequences of the architecture rather than features added on top of it.

Nothing is uploaded

There is no cloud account and no network path out for video. The only outbound network traffic in the whole system is the charging board's carbon-intensity query, and that is on a different microcontroller.

No identification

Face detection exists as a Haar cascade feeding one 10% term of the importance score. It answers "is there a face in this frame", never "whose". No embeddings are computed and nothing is stored between frames but a decaying float.

Most footage is never written

The rolling five minutes lives in RAM and is overwritten in place. Video that no detector flagged is gone within five minutes and was never on disk at any point.

Privacy zones

User-defined regions can be excluded from processing, surfacing only as abstract movement rather than as image data.

The RAM buffer has a hardware benefit too. An SD card rewritten continuously at 24 fps wears out its flash cells on a predictable schedule; DRAM does not care. Only clips that survived detection are ever committed to the storage drive.
